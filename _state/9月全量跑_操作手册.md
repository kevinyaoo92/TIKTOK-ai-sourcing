## 判据与阈值（下次跑前再确认一遍）

### 采集
- page_size = 30（热门+飙升各抓 30 行）
- source = hot+rising（两榜合并去重）

### 分析 Stage 0（清洗）
- 关键字段缺失即删：搜索量、SKU销售指数、CTOR评分、在售商品
- SKU销售指数=0 且 CTOR评分=0 → 删
- 同 L2 内 keyword 重复 → 删

### 分析 Stage 1（非商品过滤）
- 9 条正则 + 精确黑名单（促销词、价格词、支付词、平台词等）
- AI 反向黑名单（从非商品判定反向写入）

### 分析 Stage 2-5（评分）
- cohort < 3 → empty（唯一的空判据）
- 百分位：L2 内标准中位秩
- 机会分 = 100 × (0.40×Demand + 0.35×Conversion + 0.25×Competition)
- Demand = 搜索量百分位
- Conversion = 0.70×CTOR百分位 + 0.30×SKU销售指数百分位
- Competition = 1 - 在售商品百分位
- 等级（n>=30）：S>=85 / A>=75 / B>=65 / C<65
- 等级（n<30）：S>=75 / A>=65 / B>=55 / C<55（阈值降 10）

### 分析 Top N 与 AI
- Top N = 20（每个 L2 最多 20 条机会）
- 每条调 DeepSeek，产出中文名、市场判断、竞争判断、1688搜索词、风险、置信度
- AI 判非商品 → 剔除该机会，且关键词写入反向规则库
- AI 失败 → 用占位文本，机会保留（不阻塞）

## 关键规则复述

1. 采集：TikTok 榜单，每个 L2 采热门+飙升两榜，合并去重，page_size=30
2. 分析：每个 L2 独立评分，用 L2 内百分位（不用 L1 fallback）
3. 空判据：cohort < 3 判 empty（不硬撑）
4. 机会分公式：100 × (0.40×Demand + 0.35×Conversion + 0.25×Competition)
5. 等级：n>=30 用 S85/A75/B65；n<30 用 S75/A65/B55（降 10）
6. AI：只做语义理解，不算分，不排名；AI 失败用占位，不阻塞
7. 批量跑必须 force_refresh=True（否则读旧缓存）
8. 跑之前必须备份 8 月库

## 类目变化容错规则

### 已实现
采集脚本对单个 L2 有完整容错：
- try/except 包裹
- 任何异常（页面结构变、类目消失、字段改版）都被捕获
- 记入失败清单，打印错误，继续下一个 L2
- 失败清单在 data/_batches/<batch_id>/status.json

### 场景对应
- 单 L2 采集失败 -> 记失败，继续下一个
- 单 L2 入库失败 -> 记失败，继续下一个
- TikTok 页面结构改版 -> 记失败，继续下一个
- 某 L2 在 TikTok 消失 -> 记失败，继续下一个
- TikTok 新增 L2 -> 不会自动采（需手动更新任务清单）
- 单 L2 超时 >10 分钟 -> 强制退出，记失败，继续下一个
